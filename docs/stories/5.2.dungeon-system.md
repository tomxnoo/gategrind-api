# Story 5.2: dungeon-system

## Status
Completed

## Story
**As a** user,
**I want** to use my Shadow Keys to enter challenging dungeons with escalating difficulty levels,
**so that** I can earn exclusive rewards and test my progression against endgame content.

## Acceptance Criteria

### Entry System
- [x] Users can enter any unlocked dungeon level for exactly 1 Shadow Key
- [x] System validates user has sufficient aura, stats, and skill tree progression for the level
- [x] Entry is blocked if user has an active session or insufficient requirements
- [x] Levels unlock sequentially (must complete level N to unlock level N+1)
- [x] No maximum level cap - infinite progression with scaling difficulty

### Progressive Scaling
- [x] Aura requirements scale exponentially: Level 1: 100, Level 2: 150, Level 3: 225, etc. (1.5x multiplier)
- [x] Stat requirements scale progressively: Level 1: 15 each stat, scaling by 1.5x per level
- [x] Skill tree requirements increase with levels (Movement nodes required)
- [x] Trial difficulty and complexity increase with level
- [x] Rewards scale with level difficulty (better rewards for higher levels)

### Trial System
- [x] Each dungeon generates 3-5 dynamic trials using QuestGenerationService
- [x] Daily modifiers affect trial generation for variety
- [x] Trials must be completed in sequence within the session
- [x] Failed trials allow retry within the same session
- [x] Session expires after 2 hours of inactivity

### Reward System
- [x] Completion provides level-appropriate rewards (aura, items, achievements)
- [x] Rewards scale exponentially with level difficulty
- [x] Special milestone rewards at certain level thresholds (10, 25, 50, 100, etc.)
- [x] Failed sessions provide partial rewards based on trials completed

### Integration Requirements
- [x] API endpoints provide immediate responses for Discord bot integration
- [x] System integrates with existing Shadow Key economy
- [x] Progress tracking updates user statistics and achievements
- [x] Session recovery handles disconnections and timeouts gracefully

## Key Features
1. **Shadow Key Economy**: Each dungeon level requires exactly 1 Shadow Key for entry (consistent cost)
2. **Infinite Level Progression**: Unlimited dungeon levels with exponentially scaling difficulty and requirements
3. **Progressive Requirements**: Each level requires higher aura, stats (STR/END/TECH), and skill tree progression
4. **Entry Validation**: Comprehensive checks for aura, stats, skill tree nodes, and level unlock status
5. **Trial Generation**: Dynamic trials using QuestGenerationService with daily modifiers for variety
6. **Async Discord Support**: API provides immediate responses with session tracking for Discord bot integration
7. **Reward Distribution**: Completed dungeons provide Shadow Essence and exclusive rewards scaled by level difficulty
8. **Progress Tracking**: System tracks completion history, unlocked levels, and performance statistics
9. **Session Recovery**: Users can recover interrupted sessions with proper state restoration and timeout handling
10. **Skill Tree Integration**: Progressive movement node requirements that scale with dungeon level
11. **Balanced Economy**: Aura and stat requirements scale progressively to match 3 daily Shadow Keys

  class DungeonEntryRequest(BaseModel):
      ascendant_id: int = Field(..., gt=0)
      dungeon_level: int = Field(..., ge=1)

      def validate_dungeon_level(cls, v):

              raise ValueError('Dungeon level must be at least 1')
          return v

  class TrialCompletionRequest(BaseModel):
      trial_id: int = Field(..., gt=0)
      progress_data: Dict[str, Any] = Field(..., description="Movement progress data")
      
      @validator('progress_data')
      def validate_progress_data(cls, v):
          required_fields = ['reps', 'duration', 'sets', 'distance']
          if not any(field in v for field in required_fields):
              raise ValueError('Progress data must contain at least one progress field')
          return v

  """
  Database Migration for Dungeon System
  
  This migration creates all necessary tables and indexes for the dungeon system.
  """
  
  from alembic import op
  import sqlalchemy as sa
  from datetime import datetime
  
  
  def upgrade():
      """Create dungeon system tables and indexes"""
      
      # Create daily_modifiers table first (no dependencies)
      op.create_table(
          'daily_modifiers',
          sa.Column('id', sa.Integer(), autoincrement=True, nullable=False),
          sa.Column('date', sa.Date(), nullable=False, unique=True),
          sa.Column('modifier_type', sa.String(30), nullable=False),
          sa.Column('description', sa.Text(), nullable=False),
          sa.Column('stat_bonus', sa.String(20), nullable=True),
          sa.Column('difficulty_multiplier', sa.Numeric(3, 2), default=1.0),
          sa.Column('reward_multiplier', sa.Numeric(3, 2), default=1.0),
          sa.Column('created_at', sa.DateTime(timezone=True), default=datetime.utcnow),
          sa.PrimaryKeyConstraint('id'),
          sa.CheckConstraint("modifier_type IN ('strength_focus', 'endurance_boost', 'speed_challenge', 'precision_test', 'power_surge')")
      )
      
      # Create dungeon_sessions table - supports infinite levels
      op.create_table(
          'dungeon_sessions',
          sa.Column('id', sa.Integer(), autoincrement=True, nullable=False),
          sa.Column('ascendant_id', sa.Integer(), nullable=False),
          sa.Column('dungeon_level', sa.Integer(), nullable=False),
          sa.Column('shadow_keys_spent', sa.Integer(), nullable=False, default=1),  # Always 1
          sa.Column('status', sa.String(20), default='active', nullable=False),
          sa.Column('trial_data', sa.JSON(), nullable=True),
          sa.Column('daily_modifier_id', sa.Integer(), nullable=True),
          sa.Column('created_at', sa.DateTime(timezone=True), default=datetime.utcnow),
          sa.Column('updated_at', sa.DateTime(timezone=True), default=datetime.utcnow),
          sa.Column('completed_at', sa.DateTime(timezone=True), nullable=True),
          sa.Column('expires_at', sa.DateTime(timezone=True), nullable=False),
          sa.ForeignKeyConstraint(['ascendant_id'], ['ascendants.id'], ondelete='CASCADE'),
          sa.ForeignKeyConstraint(['daily_modifier_id'], ['daily_modifiers.id'], ondelete='SET NULL'),
          sa.PrimaryKeyConstraint('id'),
          sa.CheckConstraint("dungeon_level > 0"),  # No upper limit for infinite progression
          sa.CheckConstraint("status IN ('active', 'completed', 'failed', 'abandoned')")
      )
      
      # Create all indexes
      create_indexes()
  
  
  def create_indexes():
      """Create performance indexes"""
      # Dungeon Sessions indexes
      op.create_index('idx_dungeon_sessions_ascendant_level', 'dungeon_sessions', ['ascendant_id', 'dungeon_level'])
      op.create_index('idx_dungeon_sessions_status', 'dungeon_sessions', ['status'])

      op.create_index('idx_dungeon_sessions_expires_at', 'dungeon_sessions', ['expires_at'])
  
  
  def downgrade():
      """Drop dungeon system tables and indexes"""
      # Drop in reverse order due to foreign key constraints
      op.drop_table('dungeon_level_unlocks')
      op.drop_table('dungeon_rewards')
      op.drop_table('dungeon_trials')
      op.drop_table('dungeon_sessions')
      op.drop_table('daily_modifiers')

### Dungeon Level Design & Progression System
Based on epic requirements, the dungeon system provides:

**Level Progression & Unlocking:**
1. **Sequential Unlocking**: Users must complete current level to unlock the next level
2. **Level Selection**: Users can choose any previously unlocked level to replay
3. **Progressive Difficulty**: Each level has higher stat/aura requirements and harder trials
4. **Completion Tracking**: System tracks highest completed level per user

**Level Requirements (Infinite Progression - 1 Shadow Key per level):**
- **Level 1**: No requirements (tutorial level) - 1 Shadow Key
- **Level 2**: Complete Level 1 + Aura ≥ 150 + Movement I node unlocked - 1 Shadow Key
- **Level 3**: Complete Level 2 + Aura ≥ 225 + STR ≥ 15 + Movement II node unlocked - 1 Shadow Key
- **Level 4**: Complete Level 3 + Aura ≥ 338 + STR ≥ 23 + END ≥ 15 + Movement III node unlocked - 1 Shadow Key
- **Level 5**: Complete Level 4 + Aura ≥ 507 + STR ≥ 34 + END ≥ 23 + TECH ≥ 15 + Movement IV node unlocked - 1 Shadow Key
- **Level 6+**: Exponential scaling continues infinitely (Aura × 1.5, Stats × 1.5 per level) - 1 Shadow Key each

**Trial Difficulty Scaling:**
1. **Reps Scaling**: Base reps × level multiplier (1.2^level)
2. **Time Pressure**: Shorter completion windows at higher levels
3. **Movement Complexity**: Advanced movements unlock at higher levels
4. **Trial Count**: More trials per dungeon at higher levels (3 + level/2)
5. **Modifier Intensity**: Stronger daily modifiers at higher levels

**Reward Scaling:**
- **Aura Rewards**: Exponential scaling (50 × 1.3^(level-1)) = 50, 65, 85, 110, 143...
- **Shadow Essence**: Primary mystical currency (level × 5 base amount)
- **Stat Rewards**: Bonus stat points scale with level (level × 2 points distributed across STR/END/TECH)
- **Milestone Rewards**: Special rewards every 10 levels (exclusive items, achievements)

### Daily Modifier System
The modifier system provides variety and replayability:
1. **Daily Rotation**: Modifiers change daily to keep content fresh
2. **Trial Enhancement**: Modifiers affect trial generation and difficulty
3. **Reward Bonuses**: Some modifiers provide additional reward opportunities
4. **Difficulty Scaling**: Modifiers can increase or decrease challenge level
5. **Variety Types**: Movement focus, time pressure, rep multipliers, etc.
