### Data Models
**Source: [architecture/database-schema.md]**

**Core Entities:**
- **Ascendant**: Central user entity with discord_id, username, level, global_xp, stat_points (strength/endurance/technique), rested_xp_pool, aura, last_login, audit fields
- **Stat**: Individual stat progression with str_level/xp, end_level/xp, tech_level/xp
- **MovementCategory**: Content organization with string ID (e.g., "PUSH_VERTICAL"), name, description
- **SkillTreeNode**: Skill tree structure with category_id, level, name, description, unlock requirements (ascendant_level, stat_points)
- **Movement**: Individual exercises with node_id, name, xp_per_rep
- **UserSkillProgress**: User unlocks tracking (composite primary key: ascendant_id, node_id)
- **Quest**: Dynamic content with ascendant_id, title, description, source, status, target parameters, rewards, timing

**Key Relationships:**
- Ascendant ↔ Stat (one-to-one)
- Ascendant → UserSkillProgress (one-to-many)
- Ascendant → Quest (one-to-many)
- MovementCategory → SkillTreeNode (one-to-many)
- SkillTreeNode → Movement (one-to-many)
- SkillTreeNode ↔ UserSkillProgress (many-to-many through junction)

### File Locations
**Source: [architecture/project-structure.md]**
- Models location: `app/infrastructure/db/models/`
- Individual model files: `ascendant.py`, `stats.py`, `movements.py`, `quests.py`, `dungeons.py`
- Database configuration: `app/infrastructure/db/database.py`
- Migration files: `app/infrastructure/db/migrations/versions/`

### Technical Constraints
**Source: [architecture/technology-stack.md]**
- **Python**: 3.11+ required
- **SQLAlchemy**: 2.0+ with declarative models
- **Database**: NeonDB (PostgreSQL 16.x)
- **Migration Tool**: Alembic for schema management
- **Type Hints**: Required for all model definitions
- **Audit Fields**: created_at, updated_at with automatic timestamps

### Testing Standards
**Source: [architecture/technology-stack.md]**
- **Framework**: Pytest with fixtures
- **Location**: `tests/unit/test_domain/test_entities.py` and `tests/integration/test_database_operations.py`
- **Coverage**: Minimum 80% code coverage requirement
- **Test Data**: Use fixtures in `tests/fixtures/` directory
- **Database Testing**: Use test database with transaction rollback
- **Migration Testing**: Verify migrations run successfully and create expected schema

### Project Structure Notes
**Source: [architecture/project-structure.md]**
The project follows Hexagonal Architecture with clear layer separation:
- Domain entities in `app/domain/entities/`
- SQLAlchemy models in `app/infrastructure/db/models/`
- Database configuration in `app/infrastructure/db/database.py`
- Alembic configuration already exists in project root as `alembic.ini`
