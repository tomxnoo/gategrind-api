## Dev Notes

### Architecture Context
*Source: `/docs/architecture/codebase-context.md`, `/docs/architecture/api-specification.md`*

The project is implementing **GateGrind V2** using a "Brownfield x Greenfield" migration approach. The V2 API follows RESTful principles under the `/v2/` namespace with FastAPI providing automatic documentation and validation.

**Key V2 Components:**
- **V2 API Endpoints**: Located in `/app/api/v2/` with organized routers
- **V2 Schemas**: Pydantic models in `/app/api/v2/schemas/` for request/response validation
- **V2 Services**: Business logic in `/app/application/services/` shared between V1/V2
- **V2 Models**: SQLAlchemy models in `/app/infrastructure/database/models/v2/`

### Current API Client Structure
*Source: `/core/api_client.py`*

The existing `APIClient` class in `/core/api_client.py` provides:
- JWT-based authentication with Discord user tokens
- Base `_make_request` method for HTTP operations
- V1 endpoint methods for users, quests, logging, buffs, incursions, and awakening
- Development mode support with optional authentication
- Error handling and retry logic

**Current V1 Methods Include:**
- `get_user_profile()`, `update_user_profile()`
- `get_daily_quests()`, `activate_daily_quest()`
- `log_reps()`, `get_logging_stats()`
- `get_awakening_status()`, `create_incursion()`

### V2 API Design Principles
*Source: `/docs/architecture/api-specification.md`*

1. **RESTful Design**: Standard HTTP methods with resource-based URLs
2. **Versioning Strategy**: All V2 endpoints prefixed with `/v2/`
3. **Async-First**: Support for long-running operations with 202 Accepted responses
4. **Enhanced Validation**: Pydantic schemas for comprehensive request/response validation
5. **Real-Time Feedback**: All progression endpoints return updated aura scores

### V2 Endpoint Categories
*Source: `/app/api/v2/router.py`, endpoint analysis*

**Available V2 Routers:**
- **Movements**: `/v2/movements/library` - Complete skill tree structure
- **Progression**: `/v2/progression/add-xp` - XP addition and level calculations
- **Events**: `/v2/events/log-movement` - Enhanced movement logging
- **Incursions**: `/v2/incursions/*` - Modernized incursion management
- **Awakening**: `/v2/awakening/*` - Daily awakening system
- **Dungeons**: `/v2/dungeons/*` - Shadow Key dungeon system
- **Admin**: `/v2/admin/*` - Administrative functions

### V2 Schema Examples
*Source: `/app/api/v2/schemas/` analysis*

**Key Response Schemas:**
- `AscendantProfileResponse`: Comprehensive profile with stats, dungeon progress, skills, quests
- `LogMovementResponse`: Enhanced movement logging with real-time progression updates
- `AwakeningActionResponse`: Session data with quest generation and progress tracking
- `QuestCompletionResponse`: Detailed completion results with rewards and progress

### Async Response Handling
*Source: `/docs/greenfield-architecture.md`*

V2 API implements asynchronous responses for long-running operations:
- **Immediate Response**: 202 Accepted with operation ID
- **Background Processing**: Server processes request asynchronously
- **Status Polling**: Client polls for completion status
- **Discord UI**: Remains responsive during processing

### Authentication Integration
*Source: `/core/api_client.py` analysis*

Current authentication system:
- JWT tokens generated for Discord users
- System token for bot operations
- Development mode bypass for testing
- Authorization header: `Bearer {token}`

**V2 Compatibility**: Existing authentication works with V2 endpoints without modification.

### Error Handling Evolution
*Source: V2 endpoint analysis*

V2 endpoints provide enhanced error responses:
- **Structured Errors**: Pydantic-validated error schemas
- **Detailed Messages**: Specific validation failure information
- **HTTP Status Codes**: Proper RESTful status code usage
- **Error Context**: Additional context for debugging

### Migration Strategy
*Source: Epic 6 requirements*

1. **Additive Approach**: Add V2 methods alongside existing V1 methods
2. **Backward Compatibility**: Maintain existing Discord command functionality
3. **Gradual Migration**: Update Discord panels to use V2 endpoints incrementally
4. **Feature Detection**: Detect V2 availability and fallback to V1 when needed
