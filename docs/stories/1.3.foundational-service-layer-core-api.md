## Dev Notes

### Architecture Context
Based on the project's hexagonal architecture pattern, this story establishes the foundational service layer that will be used throughout the application. The service layer sits in the Application Layer (`app/application/services/`) and orchestrates business operations while coordinating with the Infrastructure Layer.

### Service Layer Design Principles
- **Single Responsibility**: Each service manages a specific domain area
- **Dependency Injection**: Services depend on abstractions (repositories) rather than concrete implementations
- **Transaction Management**: Services manage transaction boundaries for data consistency
- **Error Handling**: Comprehensive error handling with proper logging integration

### File Locations
- **Base Service**: `app/application/services/base_service.py`
- **Movement Service**: `app/application/services/movement_service.py`
- **API Router**: `app/api/v2/movements.py`
- **Dependencies**: `app/api/dependencies.py`
- **Test Files**: `tests/unit/test_services/test_movement_service.py`, `tests/integration/test_api_endpoints.py`

### Database Integration
The MovementService will integrate with the existing database models from Story 1.1:
- `MovementCategory` model for movement categories
- `SkillTreeNode` model for skill tree structure
- `Movement` model for individual movements
- Repository pattern for data access abstraction

### API Response Structure
The `/v2/movements/library` endpoint should return the complete skill tree library including:
- All movement categories with metadata
- Complete 5-level skill tree structure for each category
- Movement progressions linked to appropriate skill nodes
- Proper JSON serialization with Pydantic schemas

- **FastAPI**: Web framework for API endpoints
- **SQLAlchemy**: ORM for database operations
