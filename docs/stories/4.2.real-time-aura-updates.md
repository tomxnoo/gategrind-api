# Story 4.2: real-time-aura-updates

## Status
✅ **COMPLETED** - 2024-12-19

## Story
**As a** system,
**I want** the Aura score to be updated in real-time whenever a contributing factor changes,
**so that** the user gets immediate feedback.

## Acceptance Criteria
1. The calculate_and_update_aura method is automatically called after any event that could change the score (e.g., add_xp, unlock_skill_node).
2. All API endpoints that trigger an Aura change must return the new, updated Aura score in their response payload.

### Architecture Context
The system follows **Hexagonal Architecture** with clear separation:
- **Application Layer**: ProgressionService orchestrates aura updates
- **API Layer**: Endpoints return updated aura information
- **Infrastructure Layer**: Database persistence and response formatting

### Integration Points
Based on Story 4.1 implementation, the aura calculation method already exists. This story focuses on:
1. **Automatic Triggering**: Ensuring aura updates happen automatically
2. **Response Integration**: Including aura data in API responses
3. **Real-time Feedback**: Immediate user feedback on aura changes

### Expected Integration Flows
1. **XP Addition Flow**: User gains XP → Level up (maybe) → Stats increase (maybe) → Aura recalculated → Response includes aura change
2. **Skill Unlock Flow**: User unlocks skill → Node count increases → Aura recalculated → Response includes aura change
3. **Stat Allocation Flow**: User allocates stat points → Stats increase → Aura recalculated → Response includes aura change

### API Response Format
All endpoints that trigger aura changes should include:
```json
{
  "success": true,
  "data": {
    // ... existing response data
    "aura_update": {
      "previous_aura": 1250,
      "new_aura": 1275,
      "change": 25,
      "reason": "Strength progression"
    }
  }
}
```
